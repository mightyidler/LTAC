# LTAC

**LG TV Auto Control** — Windows에서 LG webOS TV의 전원을 간단하게 제어하는 경량 앱.

목표는 하나다. **LG TV를 일반 PC 모니터처럼 자연스럽게 켜고 끈다.** 복잡한 설정과 부가 기능을 늘리는 대신, 필요한 기능의 안정성에 집중한다.

## 원칙

- **기능은 최소화한다.** 필요한 기능만 만들고, 설정은 꼭 필요한 경우에만 추가한다.
- **실제 동작을 우선한다.** UI나 모의 테스트보다 실물 TV에서의 성공 여부를 먼저 검증한다.
- **가볍게 실행한다.** 이벤트 기반으로 동작하고, 불필요한 상시 폴링과 백그라운드 작업을 피한다.
- **단순하지만 견고하게 만든다.** 연결 실패, 타임아웃, 재시도, 복구는 내부에서 처리한다.

## 디자인

첨부한 레퍼런스처럼 **절제된 브루탈리즘(Minimal Brutalism)** 을 지향한다.

- 흑백과 회색 중심. 강조색은 꼭 필요할 때만 제한적으로 사용한다.
- 크고 선명한 타이포그래피, 과감한 여백, 명확한 정보 위계.
- 카드·아이콘·설명·테두리·그림자·애니메이션을 관성적으로 추가하지 않는다.
- 요소 하나마다 존재 이유가 있어야 한다. 불필요하면 제거한다.
- 설정 화면보다 **연결 상태와 전원 제어**를 우선한다.
- 레퍼런스의 원칙을 따르되, 화면을 그대로 복제하지 않는다.

## 기술 방향

- **핵심:** Rust / Cargo
- **TV 제어:** LG webOS SSAP(WebSocket) + Wake-on-LAN(UDP)
- **Windows 연동:** Windows API 기반 이벤트 감지 (후속 단계)
- **UI:** Tauri 2 + TypeScript / CSS (실제 전원 제어 검증 후)

핵심 전원 제어 로직은 UI와 분리하고, 처음에는 Rust CLI로 구현한다. LGTV Companion의 코드나 실행 프로세스에 의존하지 않는다.

## 개발 단계

### 1. 실제 TV 전원 ON/OFF 검증 — 최우선

**이 단계에서는 UI를 만들지 않는다.** 먼저 연결된 실제 LG TV를 제어할 수 있는지 확인한다.

1. TV IP와 MAC 주소를 입력받는다.
2. webOS 연결 및 최초 페어링을 진행하고, 승인된 인증 키를 재사용한다.
3. `off`: SSAP 전원 끄기 명령을 전송한다.
4. `on`: Wake-on-LAN 패킷을 전송한다.
5. 각 명령의 성공·실패, 응답 시간, 재연결 결과를 기록한다.
6. 반복 테스트로 실제 TV의 전원 OFF/ON을 확인한다.

**완료 기준:** 실제 TV에서 전원 끄기와 켜기가 모두 작동하고, 실패 시 원인을 확인할 수 있다. 패킷 전송 성공만으로 TV가 켜졌다고 판단하지 않는다. 켜짐은 TV에 재연결하여 확인하고, 꺼짐은 명령 결과와 실물 TV 상태를 함께 확인한다.

> TV에서 네트워크를 통한 전원 켜기 기능을 활성화해야 할 수 있다. 모델·연결 방식·대기 상태에 따라 Wake-on-LAN이 동작하지 않을 수 있다.

### 2. Windows 자동 동기화

Windows 화면 꺼짐/켜짐 및 절전/복귀 이벤트와 TV 전원을 연결한다. 중복 명령 방지, 연결 복구, 짧은 상태 변화에 대한 처리 등 안정성부터 검증한다.

### 3. 최소한의 데스크톱 UI

Tauri 창과 시스템 트레이를 추가한다. TV 연결 상태, 수동 ON/OFF, 전원 자동 동기화, Windows 시작 시 실행 등 **필수 항목만** 제공한다.

## 지금 하지 않는 것

추가 기기 관리, 고급 자동화 규칙, 복잡한 설정 페이지, TV 리모컨 기능, 불필요한 시각 효과, 별도의 상주 서비스는 필요성이 검증되기 전까지 구현하지 않는다.

**개발 순서: 실제 제어 검증 → 자동화 안정성 → UI.**
