# LTAC — LG TV 연결 UX

## 목표

**TV를 찾고 → 선택하고 → TV에서 승인하면 연결 완료.**

LTAC의 연결 과정은 IP 주소, MAC 주소, 포트, 프로토콜을 사용자가 몰라도 끝나야 한다. 기술적인 설정을 줄이는 것이 아니라 **사용자가 직접 설정할 일을 없애는 것**이 원칙이다.

## 첫 연결 흐름

1. **자동 검색** — 앱을 열면 같은 로컬 네트워크의 LG webOS TV를 자동으로 찾는다. 검색 중임을 알리고 발견한 TV는 이름/모델로 구분해 보여준다.
2. **TV 선택** — 사용자는 목록에서 자신의 TV를 한 번 선택한다. IP나 MAC 주소는 표시하거나 요구하지 않는다.
3. **연결 승인** — LTAC이 페어링을 요청한다. TV에 승인 창이 나타나면 리모컨으로 승인하도록 간단히 안내한다.
4. **연결 완료** — TV 식별 정보와 인증 키를 저장하고 연결 상태를 확인한다. 이후에는 별도 설정 없이 해당 TV를 사용한다.

첫 연결 이후 기본 화면에는 **TV 이름 · 연결 상태 · 전원 동기화 · 수동 ON/OFF**만 표시한다.

## 내부 처리

- **기기 발견:** SSDP 등 로컬 네트워크 탐색으로 LG webOS TV를 찾아 중복 기기를 정리한다. 자동 검색은 TV가 켜져 있고 같은 네트워크에서 검색이 허용되는 상황을 전제로 한다.
- **페어링:** LG webOS WebSocket(SSAP)에 연결해 TV의 승인을 받는다. 승인 후 발급받은 `client-key`는 Windows 사용자 계정 범위에서 보호해 저장한다.
- **주소 관리:** IP 주소는 바뀔 수 있는 연결 정보로 취급한다. 재연결에 실패하거나 네트워크가 변경되면 TV를 다시 탐색하고, 식별 정보가 일치하는지 확인한 뒤 주소를 갱신한다.
- **MAC 주소:** TV가 제공하는 네트워크 정보와 Windows의 네트워크 이웃 정보를 순서대로 확인한다. MAC 주소는 모델·연결 방식·네트워크 구성에 따라 자동으로 얻지 못할 수 있다. 확인되지 않은 값을 추측해 저장하지 않는다.
- **전원 제어:** OFF는 인증된 webOS 명령으로, ON은 해당 TV의 실제 네트워크 인터페이스에 대한 Wake-on-LAN으로 처리한다. **패킷 전송 성공과 실제 TV 켜짐은 구분**한다.
- **자동 복구:** 저장된 TV가 일시적으로 응답하지 않으면 제한적으로 재시도한다. 실패 원인을 기록하되 사용자에게는 필요한 행동만 안내한다.

## 예외 상황의 UX

| 상황 | 사용자에게 보여줄 안내 |
|---|---|
| TV가 검색되지 않음 | **TV를 찾지 못했어요.** TV 전원과 PC의 네트워크 연결을 확인하고 **다시 검색** |
| TV에서 승인을 기다리는 중 | **TV에서 연결을 승인해 주세요.** |
| 페어링 거절 또는 시간 초과 | **연결하지 못했어요.** 다시 시도 |
| 전원 끄기는 되지만 켜기는 실패 | **TV를 자동으로 켤 수 없어요.** TV의 네트워크 켜기 설정 확인 |
| IP 주소 변경 또는 일시적 단절 | 백그라운드에서 재검색·재연결, 복구 불가 시에만 안내 |

자동 검색 실패 시에만 **수동 IP 연결**을 보조 경로로 제공한다. MAC 주소 자동 획득이 실패한 경우에는 전원 ON 검증 단계에서만 추가 설정을 요청한다. 불가능한 동작을 '연결 완료'로 표시하지 않는다.

## UI 원칙

- **절제된 브루탈리즘:** 흑백·회색, 강한 타이포그래피, 정확한 여백, 필요한 곳에만 포인트 색상.
- 한 화면에 한 가지 행동. 불필요한 카드, 아이콘, 설명, 고급 옵션, 장식은 제거한다.
- IP·MAC·포트·인증 키는 기본 UI에서 숨긴다. 진단이 필요할 때만 별도로 확인할 수 있게 한다.
- 로딩·승인 대기·연결 성공·실패 상태를 명확히 구분한다. 클릭 결과를 추측으로 성공 처리하지 않는다.

## 1차 개발 및 검증

**UI 제작보다 실기 연결 검증이 먼저다.** Rust CLI에서 다음 전체 흐름을 우선 구현한다.

`discover → select → pair → save → off → on → verify`

완료 기준:

- 사용자가 IP/MAC 주소를 미리 입력하지 않고 TV를 발견하고 선택할 수 있다.
- 실제 TV에서 페어링 승인이 이루어지고 재실행 후에도 연결 정보가 유지된다.
- 실제 TV의 전원 OFF 및 ON을 각각 확인하고, 실패 단계와 원인을 구분해 출력한다.
- MAC 주소 자동 획득 또는 WOL이 지원되지 않는 환경에서는 한계를 명확히 보고하고 필요한 경우에만 보조 설정을 제시한다.

실기 검증에 성공하면 같은 Rust 모듈을 Tauri UI에 연결한다. **첫 단계에서 기능을 늘리지 않는다.**
