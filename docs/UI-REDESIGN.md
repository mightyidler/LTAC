# LTAC UI 재설계 · 2026-10-18

실행: 프로젝트 루트에서 `npm run dev` → http://127.0.0.1:1420/

375×500px 앱과 상하좌우 4px 여백을 합친 창 크기는 383×508px이다. 폭 375px은 JSON의 내부 폭 343px과 좌우 패딩 16px에서 확인했다. 높이 500px은 제공된 이미지의 화면 비율에서 정했다. 앱 내부의 #1D1D1D 배경, #383838 테두리, 반경 12px은 JSON을 따른다. 창 외부와 로딩 캔버스는 투명하며 운영체제 제목 표시줄과 테두리는 없다. Bald와 동일한 Tauri `decorations: false`, `transparent: true`, `shadow: false` 구조다.

기준 원문은 `docs/design/ui-spec.json`에 그대로 보관했다. Pretendard 가변 폰트는 로컬 번들로 로드하고 OFL을 함께 포함했다. 제공된 Vectors의 원본 SVG를 크기대로 사용하며 `currentColor`로 각 위치의 색상을 지정한다. 제공되지 않은 체크 표시는 SVG 경로로 구현했다.

후속 요청으로 모든 텍스트의 굵기를 100씩 낮췄다. 기본 400→300, 기존 500→400, 기존 600→500이며 웹 테스트 도구의 기본 굵은 제목도 700→600으로 맞췄다. 가변 폰트의 지원 범위 선언은 텍스트 굵기가 아니므로 유지한다.

강조색은 첨부 이미지에 적힌 12개 RGB 수치를 ui/src/palette.ts에 그대로 기록했다. P3는 참고 정보이며 실제 CSS는 rgb(R G B), WebGL은 기본 sRGB 출력을 사용한다. 오류·실패는 빨강 (255, 66, 69), ON 스위치는 초록 (48, 209, 88)이다. 별도의 P3 변환·사용자 정의 출력 셰이더는 제거했다. 흰색은 #FFFFFF이다.

장치 리스트·장치 선택·스크롤 예시의 최신 원문은 `docs/design/choose-spec.json`이다. 해당 세 화면은 이 후속 JSON을 우선한다. 기본 콘텐츠 여백은 좌우 16px이다. hover 표면만 바깥 8px까지 확장되도록 목록 바깥 패딩 8px·항목 안쪽 패딩 8px을 합친다. 제목과 검색 상태도 16px에 맞춘다. 항목 패딩은 상하 12px·좌우 8px, 항목 반경은 8px, hover 배경은 #FFFFFF08이다. 구분선은 왼쪽 40px·오른쪽 8px을 비우고 양옆 항목과 4px 간격을 둔다.

홈의 후속 디자인은 `docs/design/home-spec.json`에 보관했다. 홈 좌측 상단은 반경 14px·배경 #FFFFFF14의 28×28px 단일 버튼이다. 제공된 Plus·Chevron 형태를 바탕으로 16×16px SVG의 동일 경로를 변형한다. 선은 1.6px, 실제 벡터 높이는 9⅓px이며 중간 프레임마다 벡터 경계 중심을 (8, 8)에 맞춘다. 전환 중 크기를 scale하지 않는다. 헤더·More·새로고침·TV 타일의 아이콘은 grid/flex 가운데 정렬을 명시한다. 홈에서는 +, 추가·수동 입력·연결 화면에서는 뒤로 동작이며 +↔뒤로는 두 개의 선이 같은 관절을 공유하며 350ms ease-in-out으로 회전·접힘을 이어간다. 뒤쪽 두 팔이 앞쪽 두 팔에 포개져 쉐브론을 만들고 역방향은 같은 궤적을 펼친다. 네 팔의 길이는 0이 되지 않고 선 두께는 1.6px로 유지한다. 최초 등록의 장치 선택 화면에서는 표시하지 않는다. 검색 도중에도 뒤로 갈 수 있으며, 네이티브 검색 future를 취소해 완료를 기다리지 않고 홈으로 돌아간다. 취소된 웹 요청의 늦은 결과도 현재 화면을 덮어쓰지 않는다. More 버튼의 닫힌 배경 #2F2F2F와 테두리 #FFFFFF0A도 후속 JSON을 따른다.

## 직접 테스트

앱 오른쪽 도구에서 화면, 연결 결과, 응답 대기 시간, 검색 결과 수, 앱 외부 배경을 선택한다. 이 도구는 웹 개발 모드에만 표시한다.

- 장치 리스트, 선택 상태, 스크롤 목록, 장치 없음
- 직접 입력의 빈 상태와 입력 완료 상태
- 연결 요청, 완료 모션, 실패 모션과 재시도
- 홈 상단 +의 기기 추가와 More 메뉴의 정보 수정·삭제
- 전원 동기화, 절전 단축키 스위치, 단축키 지정
- 설정 오류

목록에서 장치를 선택한 뒤 연결을 누르면 선택한 응답 지연 이후 성공 또는 실패로 진행한다. 성공은 홈까지 이어진다. 직접 입력의 IP는 4칸, 선택 MAC은 6칸이며 전체 주소 붙여넣기와 칸 이동을 지원한다. 직접 입력에 진입하면 첫 IP 칸에 자동 포커스한다. IP·MAC은 하나의 입력 순서로 연결하며 IP 마지막 칸에서 다음 칸으로 이동하면 첫 MAC 칸을 선택한다. 세 자리 IP 또는 세 번째 숫자를 붙일 수 없는 두 자리 IP는 자동 이동하고, 짧은 구간은 점·Enter·오른쪽 방향키로 완료한다. IP 전체 주소 붙여넣기는 바로 첫 MAC 칸으로 이동한다. 단축키 버튼을 누르면 버튼이 흰색 배경·어두운 글자로 바뀌고 `키를 눌러주세요`를 표시한다. 평상시 반투명 배경과 명확히 구분하며 저장·취소·다른 곳 클릭 시 원래 스타일로 돌아간다. 입력한 키를 저장한다. 단일 키·Shift 조합·기호·숫자패드·미디어 키도 받으며 Ctrl/Alt/Win을 필수로 요구하지 않는다. Esc만 누르면 지정을 취소하고, 다른 곳을 클릭해도 취소한다. Windows가 해당 키 등록을 거절하면 버튼에 `다른 키 사용`을 표시한다. 버튼의 상태 문구는 text-states-swap의 블러·불투명도·4px 이동으로 전환한다. 웹 테스트는 실제 기기를 제어하거나 OS 단축키를 등록하지 않는다. 새로고침하면 테스트 데이터가 초기화된다.

## 모션

연결 로딩·성공·실패 콘텐츠는 헤더를 포함한 앱 전체 영역의 중앙에 배치한다. 헤더 높이를 상단에서 제외하지 않고 제목·서브타이틀·인디케이터 묶음을 가운데 정렬한다.

[psyonline의 Her / OS1 로더](https://codepen.io/psyonline/pen/yayYWg)의 곡선 방정식, 튜브 형상, 회전, 가속, Y축 회전과 원 전환을 Three.js로 이식했다. 클릭 유지에 해당하는 상태는 실제 연결 결과가 결정한다. 대기 회전만 기존 2.1rad/s에서 4.2rad/s로 높였다. 완료·실패 이후의 가속·원 전환은 원본의 4000ms로 복원했다. 원 완성 시 체크·X 그리기와 텍스트 전환이 함께 시작한다. 체크·X는 80ms 뒤 500ms 동안 그리며, 제목·안내 문구는 300ms 동안 4px 블러·불투명도로 사라지고 새 문구가 300ms 동안 나타난다. 연결 대기 문구는 `TV에서 연결을 허용해 주세요` 한 줄이며 모든 결과의 제목 높이를 32px로 유지한다. 제목과 기기 이름 사이에는 8px 간격을 둔다. 완료 화면은 체크 이후 900ms 유지하고 홈으로 이동한다. 모션 줄이기에서는 이 대기를 생략한다.

140×48px 안에 들어오도록 카메라와 이동 거리를 조정했다. 원본의 배경색 평면은 제외한다. 대기 리본의 재질색은 #FFFFFF이며 앞쪽은 선명하고 뒤쪽은 투명하게 보이도록 깊이별 알파 0.16–1.0을 적용한다. 원 전환 중 카메라 맞춤 이동에도 알파 기준 깊이가 함께 이동한다. 색상과 투명도는 별개로 처리한다. CSS 대체 로더도 투명도 변화를 주지 않는다. P3 출력 설정과 추가 변환 셰이더를 제거하고 기본 sRGB로 출력한다. 최종 원은 카메라 투영으로 역산한 반경 15.84px·두께 1.8px·192분할의 WebGL 원으로 유지한다. SVG로 마지막 프레임을 교체하지 않으며 SVG 원은 WebGL 미지원 환경에만 사용한다. 체크·X도 같은 1.8px 선으로 중앙 (70, 24)에 배치한다. 모션 줄이기 설정에서는 회전·전환을 생략하고 최종 상태를 표시한다. WebGL이 불가능한 환경에는 배경이 투명한 CSS 대체 표시가 있다.

[transitions.dev](https://transitions.dev/library.html)의 로컬 `transitions-dev` 스킬을 적용했다. More 버튼이 메뉴 표면으로 확장되는 morph, 방향에 따른 페이지 이동, 스위치와 체크 경로 그리기를 사용한다. 메뉴는 바깥 클릭·Esc로 닫히고 방향키로 탐색한다. More 메뉴는 정보 수정·삭제만 표시하며 폭은 기존 112px을 유지하고 높이는 두 행(각 36px)과 상하 패딩(각 3px)의 합인 78px이다. 표면 배경 #2F2F2F99·테두리 #FFFFFF0A·반경 12px·배경 블러 24px·그림자 0 4px 16px #00000014를 적용한다. 각 항목의 아이콘·문구는 왼쪽 기준선에 정렬하고 반경 9px·패딩 10px·아이콘 간격 8px이며 제공된 Edit·Delete SVG를 16px로 표시한다. 정보 수정 13px·삭제 12px·행간 16px·자간 -1%(-0.01em)·흰색이며 Medium 기준에서 앞선 요청대로 weight를 100 낮춘 400을 사용한다. 삭제의 이전 빨강 지정은 새 JSON의 흰색으로 교체한다. 검색 결과·등록 기기는 키로 DOM을 유지하고 변경된 항목만 등장·접힘 모션을 진행한다. 연결 요청·완료·실패는 한 화면 안에서 text-states-swap으로 문구를 바꾸고 원 완성 시점에 맞춘다. 수동 전원 버튼, 전원 상태 대시보드, OFF/ON 확인 단계와 시작 프로그램 설정은 새 UI에서 제거했다.

검색 중에는 문구·shimmer 없이 가로 로딩바만 표시한다. 바는 1400ms 주기로 반복한다. 목록 바깥 8px 안에 추가 8px 여백을 두므로 바는 기본 16px에 맞는다. 로컬 스킬의 `07-panel-reveal.md`로 목록·검색·장치 없음의 콘텐츠 영역만 2px 블러·불투명도로 전환하고 Y 이동은 0으로 설정한다. 기존에는 250ms 페이지 모션 뒤에도 400ms 패널의 8px 이동이 남고, ResizeObserver가 측정한 높이를 300ms 동안 다시 적용했다. 이 중첩 구조를 제거해 활성 패널이 일반 흐름에서 높이를 결정하게 했다. 스크롤 자동 앵커 보정도 끄고 재검색 시작 시 스크롤을 맨 위로 맞춘다. 번들 폰트는 preload 및 첫 마운트 전 로딩으로 나중에 글꼴 메트릭이 바뀌는 재배치를 방지한다. 제목·하단 버튼은 유지한다. 장치 없음 화면은 제공된 TV 아이콘을 48px 타일에 배치하고 기존 문구를 중앙 정렬하며 별도 버튼이나 문구는 추가하지 않았다. 비활성 영역은 inert·aria-hidden으로 탐색에서 제외하고 `prefers-reduced-motion`에서는 반복·전환 모션을 생략한다.

검색 완료 시에는 로딩 표면을 150ms 동안 지우면서 첫 행부터 바로 나타낸다. 각 행 전체가 위쪽 8px에서 최종 위치로 250ms 동안 내려와 자리 잡고 40ms 간격으로 이어진다. 총 stagger는 240ms로 제한한다. 아이콘·이름의 개별 블러는 제거했다. 행 이동은 transform으로만 실행하므로 제목·하단 버튼·다른 행의 레이아웃은 밀리지 않는다. 부모 목록 전체의 중복 fade는 제거했다. 최소 콘텐츠 공간을 확보해 이전 목록이 로딩바 높이로 잘려 없어지지 않도록 한다.

연결 결과의 문구는 타이틀·서브타이틀 두 곳만 사용한다. 실패 시 기기 이름 자리를 `TV 전원과 네트워크를 확인해주세요`로 교체한다. 성공·실패 모두 두 문구가 원 완성 시점부터 함께 blur·불투명도로 사라졌다 나타난다. 성공 시 기기 이름이 같아도 모션을 재생하며 동일 상태 재렌더링 때는 반복하지 않는다.

## 데스크톱 연결

Tauri에서는 실제 검색·페어링·기기 저장·수정·삭제·동기화·전역 절전 단축키 명령을 사용한다. 등록 기기는 `%LOCALAPPDATA%/LTAC/devices/`에 저장하고 기존 단일 기기 설정은 최초 실행 시 가져온다. 보호된 인증 키를 UI에 보내지 않는다. 일반 데스크톱 모드의 동기화는 등록된 기기들에 Windows 이벤트를 전달한다. 자동 켜기 기능이 검증되었다고 임의로 기록하지 않으며 기존 `wake_verified`는 유지한다.

기존 Windows 서비스는 단일 TV를 담당한다. 설치된 서비스 모드에서 새 페어링과 기기 수정·삭제는 기존 제약대로 거절하고 오류로 알린다. 서비스의 설치·다중 기기 지원은 이번 UI 작업에서 변경하지 않았다. 기존 서비스 설치용 CLI는 물리적 전원 검증 조건을 계속 요구한다.

## 검증 범위

사용자 요청에 따라 화면 자동 탐색과 스크린샷 반복 캡처를 하지 않았다. 초기 렌더링과 후속 수정의 MAC a1→A1 입력, 웹 단축키 Ctrl+Alt+K 저장만 최소 확인했다. TypeScript/Vite 프로덕션 빌드, Tauri Rust 컴파일, 로더의 투영 좌표 계산으로 잘림 여부를 검사했다. 실제 TV, 창 드래그·최소화, 전역 단축키, PC 절전·복귀, 서비스 동작은 실행하지 않았다. 이 문서의 구현 설명은 실기 성공을 의미하지 않는다.

검사 명령:

```powershell
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
node tools/check-indicator-bounds.mjs
node tools/check-ui-inputs.mjs
node tools/check-page-motion.mjs
node tools/check-shortcut-motion.mjs
```

이번 전달은 소스와 웹 개발 UI이며, 기존 `releases/`의 실행 파일을 교체하지 않았다.

홈 업데이트: 전원 동기화 → 절전 단축키·단축키 설정 → 업데이트 순서이며 업데이트 앞에 구분선을 둔다. JSON의 기존 설정 행·버전 설명과 단축키 버튼을 재사용한다. 공통 swapButtonLabel이 기존 Text states swap 모션과 독립 문구 너비를 양쪽 버튼에 적용한다. 네이티브 GitHub 서명 업데이트와 웹 상태 테스트, 배포 제외 규칙은 [UPDATES.md](./UPDATES.md)에 기록했다.

공통 페이지 안정화: 웹 테스트 모듈과 스타일, 폰트 로딩을 먼저 마친 뒤 선택된 화면을 한 번만 그린다. 최초 마운트는 모션 없이 최종 위치에 표시한다. 이후 모든 페이지를 같은 좌우 모션으로 교체하지 않고 실제 전진·뒤로가기와 상태 전환을 구분한다. 웹 미리보기의 앱 상단 위치는 고정하며 실패 화면 직접 진입도 최종 문구를 바로 사용한다.

footer의 별도 배경 레이어에 40px blur를 적용했다. Chromium/WebView2의 장치 선택 스크롤바 track은 헤더 52px·하단 버튼 영역 68px만 비우며 기존의 상하 추가 4px 여백을 제거했다. 고정 헤더·버튼 영역과 겹치지 않는다. 홈의 track도 헤더 높이와 같은 52px에서 시작해 상단 4px 갭을 제거했고 하단 여백은 8px이다. 홈이 최상단에서 벗어나면 연결 페이지와 동일한 .scrolled 헤더 하단 구분선·배경 블러를 적용하며 최상단으로 돌아오면 해제한다. 떠나는 홈 페이지의 스크롤 이벤트는 현재 헤더 상태에 영향을 주지 않는다.

정보 수정에서는 MAC 라벨의 (선택)을 표시하지 않는다. 직접 입력은 기존 선택 라벨을 유지한다. 단축키 설정은 절전 단축키 ON일 때만 나타난다. transitions.dev accordion 높이는 펼칠 때 350ms·접을 때 250ms이며, 안의 문구·버튼 전체는 40ms 뒤 250ms 동안 4px 이동·4px blur·불투명도로 나타난다. 닫을 때는 내용이 즉시 150ms 동안 흐려지고 높이 접힘은 80ms 뒤 시작한다. 높이에 의해 글자가 바로 잘리기 전에 페이드가 먼저 진행되며 하단에는 8px 여유를 둔다. OFF인 영역은 접근성 탐색에서도 제외한다. 홈 하단 인라인 오류는 제거하고 앱 하단의 transitions.dev toast로 바꿨다. 토스트는 내용 너비의 작은 유리 표면으로 하단 중앙에 뜨고 오류일 때 빨강 점을 표시한다. 닫기 버튼과 hover/focus 일시 정지는 없으며 4.5초 뒤 자동으로 사라진다. 앱 레이아웃과 버튼 입력을 차지하지 않는다. 실제 입력값의 형식 안내는 해당 필드 옆에 유지하고 단축키 입력 안내는 토스트를 사용하지 않는다.

앱 텍스트·영역은 드래그로 선택되지 않고, 입력 칸의 선택 배경도 투명하다. 앱 안의 컨트롤은 Tab 순서에서 제외하고 포커스 외곽선·입력 포커스 테두리를 표시하지 않는다. 입력값 편집·붙여넣기와 프로그램에 의한 칸 이동은 유지한다. 단축키 지정 중 Tab을 누르면 포커스 이동 대신 단축키 입력으로 처리한다.

잘림 수정: 단축키 라벨의 overflow:hidden·말줄임을 제거하고 행간 18px·상하 5px의 내부 여유를 확보했다. 긴 조합은 줄바꿈하며 버튼은 내용 높이에 맞춰 늘어난다. 단축키 텍스트는 Text states swap 원본의 4px Y 이동을 사용하며 버튼 overflow를 열고 아코디언 바닥에는 8px 여유를 둬 G 같은 글자와 전환 blur가 잘리지 않게 한다. 기기 이름의 말줄임과 설정 설명의 강제 한 줄도 제거했다. 제목·안내·입력 화면의 잘린 텍스트 여부와 140×48px 로더의 투영 범위를 점검했다.

후속 입력 수정: IP·MAC의 빈 칸에 포커스를 두면 가운데 정렬된 플레이스홀더의 왼쪽에 커서를 표시한다. MAC 편집은 영문·숫자를 받고 자동으로 대문자로 바꾼다. 실제 MAC에 사용할 수 없는 G–Z를 입력하면 값을 지우지 않고 형식 안내를 표시한다.

Windows 절전 호출에는 [Microsoft SetSuspendState 문서](https://learn.microsoft.com/en-us/windows/win32/api/powrprof/nf-powrprof-setsuspendstate)에 따라 SeShutdownPrivilege 활성화·오류 확인·기존 토큰 상태 복원을 추가했다. 호출 전후의 복원은 RAII로 처리하며 실제 PC 절전·복귀는 실행하지 않았다.

전원 동기화의 신규 기본값은 ON이다. 기존에 저장한 OFF는 유지한다. 최초 연결 성공 후 실제 동기화를 시작하고, MAC 누락 등의 동기화 오류는 홈에 표시한다. 단축키 캡처는 입력 버튼에 포커스를 주고 capture 단계에서 처리한다. 지정한 키는 웹 테스트 데이터에 저장하거나 데스크톱에서 Windows RegisterHotKey로 등록한다. 실제 등록이 불가능한 키만 버튼 안에서 다시 입력하도록 알린다.


홈 기기 없음 상태에서도 '기기 목록' 제목은 기존 왼쪽 정렬과 #FFFFFFB2·13px·18px 행간을 유지한다. 안내는 '연결된 기기가 없습니다' 한 줄, 중앙 정렬, 상하 16px 패딩, #FFFFFF70·13px·18px 행간·-1%(-0.01em) 자간이다. 등록 기기가 생기면 안내가 접히고 마지막 기기를 삭제하면 목록 항목의 접힘과 함께 나타난다. 웹 테스트 도구의 '홈 (기기 없음)' 또는 ?screen=home-empty에서 바로 확인한다.

페이지 이동: 홈→기기 추가, 장치 선택→직접 입력, 홈→정보 수정, 장치 선택·직접 입력→연결 요청은 전진이며 뒤로 버튼·정보 수정 저장은 복귀다. iOS식 push/pop으로 전면 페이지가 100% 이동하고 뒤쪽 페이지는 30%만 이동한다. 350ms·cubic-bezier(.32,.72,0,1)를 적용하며 방향 페이징에는 블러·페이드를 섞지 않는다. 그 밖의 방향 없는 화면 교체는 250ms 페이드·4px 블러다. 연결 완료→홈은 먼저 완료 화면이 250ms 동안 opacity 0·blur 6px로 사라진 후 홈 제목·기기 행·설정 항목을 350ms·40ms 간격(최대 160ms 지연)의 페이드·3px 블러·8px 세로 이동으로 표시한다. 홈은 완료 화면의 사라짐이 끝나기 전까지 가리고 입력도 받지 않는다. 새 이동이 들어오면 기존 전환과 예약된 홈 등장을 취소한다. 창 최소화·닫기는 페이지 밖의 동일 DOM을 유지하고 페이지 모션·홈 등장 대상에서 제외한다. 모션 줄이기에서는 바로 최종 화면을 표시한다.

단축키 지정·변경 문구는 설치된 transitions-dev 스킬의 Text states swap 훅(.t-text-swap / .is-exit / .is-enter-start)과 34-text-swap-soft.md의 독립 문구 레이어 방식을 사용한다. 기존 문구는 위로 4px 이동하며 opacity 0·blur 2px로 사라지고, 교체 문구는 아래 4px에서 원래 위치로 들어온다. 버튼에서 Y 이동을 0으로 막던 예외는 제거했고 토큰을 버튼 범위에 명시했다. 모션 줄이기 가드는 유지한다.

연결 인디케이터 마감: 완료 가속은 기존 4초를 유지하며 실제 경과 시간의 적분으로 회전각을 정해 프레임 수에 따른 종단 위상을 없앴다. 완료 시작 300ms 동안 기본 회전 속도를 이어 대기→가속의 급감속을 제거했다. 원으로 합쳐질 때의 0.9→1 크기 변화는 제거하고 리본과 원의 알파를 smoothstep으로 겹쳐 밝기가 갑자기 내려가지 않도록 한다. 원이 완성되면 문구 전환과 체크의 짧은 150ms 페이드·1px 블러를 시작하고 80ms 뒤 500ms ease-in-out으로 체크를 그린다. 체크는 회전하거나 상하로 움직이지 않는다. 실패 X는 두 독립 경로를 40ms 간격으로 그리며 두 번째 선이 끝난 뒤 완료를 알린다. 원→체크 시 WebGL/SVG 원 교체나 크기·위치 변화가 없다. 수치 검사로 투영 중심·반경·두께·140×48 범위·회전 속도 연속성과 합성 알파의 빈 구간 부재를 확인하고 실제 결과 화면은 한 번만 확인했다.

단축키 버튼 타이밍 보정: 두 문구를 각각 최종 줄 너비로 고정하고 같은 중심에 겹친다. 버튼이 늘어나는 동안에도 새 문구가 좁은 중간 너비에 맞춰 다시 줄바꿈되지 않는다. 기존 문구는 350ms 동안 흐려지고, 새 문구는 120ms 뒤 250ms 동안 나타나므로 두 문구가 겹쳐 이어지며 숨긴 채 크기 변화를 기다리던 빈 구간은 없다. 긴 키 조합의 의도한 최종 줄바꿈은 유지한다. 배경·테두리·글자색과 크기는 350ms로 변화한다. 축소 시에는 기존 긴 문구가 사라진 뒤 크기를 줄여 글자가 박스 밖으로 튀어나가지 않게 한다. 빠르게 끝난 입력·저장 상태는 80ms 동안 최신 상태로 묶고 문구 등장 중 갱신은 다음 전환으로 보관한다. 페이지 이동으로 ID가 제거된 이전 버튼의 예약 전환은 중단하며 모션 줄이기에서는 즉시 최종 상태를 표시한다. 합성 시계 검사로 독립 줄 너비·겹침·축소 지연·빠른 저장·이동 취소·모션 줄이기를 확인했다. 실제 브라우저 중간 프레임에서도 새 안내 문구의 줄 높이가 18px로 유지되는 것을 확인했다.

단축키 줄바꿈 후속 수정: 화면 좌표(getBoundingClientRect) 대신 배율·페이지 변환이 반영되지 않는 CSS 레이아웃 치수로 문구와 버튼을 측정한다. 소수점 너비를 포함해 여유를 확보하고 짧은 문구는 white-space:pre로 고정한다. 최종 버튼 너비를 넘어서는 긴 키 조합만 최종 너비에서 줄바꿈하며 그 줄 배치는 크기 전환 중에도 고정한다. '키를 눌러주세요'는 기존 400에서 500으로 올리고 해당 두께로 너비를 측정한다. 겹치는 이전 문구는 이전 두께를 유지한다.

웹 테스트 도구의 '홈 기기 수' 입력은 0–100개를 지정한다. 홈·설정 오류 화면에서는 입력 즉시 목록에 반영하고, 0개에서는 기존 빈 목록 디자인을 표시한다. 별도의 '홈 (기기 없음)' 화면을 고르면 입력값도 0으로 맞춘다. 이후 양수로 입력하면 홈 화면으로 전환한다. 실제 등록 데이터에는 영향을 주지 않는다.

장치 선택 행의 구분선은 클릭 버튼 바깥 .device-choice-row에 둔다. 버튼의 눌림 scale 모션에는 아이콘·이름·선택 표시·hover 배경만 참여하고, 구분선과 행 간격은 고정한다. 선택 상태와 disabled·option 역할은 내부 버튼에 유지하며 검색 결과의 순차 등장은 행 래퍼에서 실행한다.
